# Omniverse Mapping Order

This is the first compiler-facing mapping specification for the Design Pathology branch.

## Canonical order

1. Capture source.
2. Extract concept seed.
3. Assign observer lens.
4. Classify epistemic state.
5. Detect contradiction.
6. Generate candidate interpretations.
7. Translate the selected interpretation into a design requirement.
8. Spawn an isolated descendant configuration.
9. Execute or simulate within the declared environment.
10. Compare expected versus observed result.
11. Grade provenance and evidence.
12. Route the descendant to promote, revise, quarantine, or preserve-as-fiction.

## Source contract

- Preserve original source bytes.
- Require provenance.
- Never silently overwrite an ancestor.
- Never silently upgrade a claim from speculative/fictional to verified.

## Book-to-Universe-Node portal

The first software portal is a controlled translation contract from a provenance-addressed book seed into an isolated Universe Node configuration.

The portal transfers data and declared semantics only. It does not transfer authority.

## Metacognitive state machine

Each descendant records:

- prior state,
- alternatives considered,
- selected alternative,
- rule or score used to select it,
- rejected alternatives,
- resulting observed state.

## First mission

Input:
- source passage,
- concept seed,
- observer lens.

Output:
- Universe Node configuration,
- epistemic class,
- simulation result,
- contradiction record,
- descendant design seed.

## Promotion gate

A candidate can advance only when:

- source provenance remains intact,
- no claim-class escalation occurred without evidence,
- the descendant can be reproduced from recorded inputs,
- the original source remains unchanged.

Human choice remains the final authority for promotion outside the sandbox.
